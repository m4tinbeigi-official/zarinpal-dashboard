# داشبورد تحلیلی پذیرندگان زرین‌پال

محصول تحلیلی فارسی و RTL برای چالش زرین‌پال. داده خام تراکنش‌ها را به KPI، الگوی زمانی، تحلیل مشتری، بنچ‌مارک محرمانه صنفی، سلامت پرداخت و پاسخ‌های تحلیلی قابل استناد تبدیل می‌کند.

## اجرا

پیش‌نیاز: Node.js 20 یا جدیدتر.

```powershell
cd E:\2-Hack\zarinpal-dashboard
npm install
npm run prepare-data
npm run dev
```

برنامه در `http://localhost:3000` اجرا می‌شود. اگر فایل‌های تجمیعی موجود باشند، اجرای دوباره `prepare-data` لازم نیست؛ اما برای بازتولید تحلیل‌ها از CSV اصلی استفاده می‌شود.

## کنترل کیفیت

```powershell
npm run test:data
npm run lint
npm run build
```

`test:data` سازگاری KPI با تجمیع‌های روزانه، تعداد artifactها و عدم نشت `payer_card_key` یا شناسه کارت خام را بررسی می‌کند.

## روش‌شناسی داده

- منبع داده: `../other_challenge_data.csv/challenge_data.csv` با 2,213,289 ردیف.
- جلسه موفق: `session_status` برابر `Verified` یا `Paid`، با شمارش حداکثر یک بار برای هر `session_key` در هر پذیرنده.
- عارضه‌یابی: تلاش‌های پرداخت در سطح هر ردیف و `try_status` بررسی می‌شوند تا retryها قابل مشاهده بمانند.
- واحد منبع ریال است؛ تمامی مبلغ‌های UI با تقسیم بر 10 و برچسب «تومان» نمایش داده می‌شوند.
- `adjusted_fee` کارمزد واقعی زرین‌پال نیست و فقط به عنوان شاخص تعدیل‌شده برای مقایسه نسبی استفاده می‌شود.
- `payer_card_key` فقط در زمان آماده‌سازی برای تجمیع مشتریان استفاده می‌شود و هیچ مقدار خامی به مرورگر ارسال نمی‌شود.
- بنچ‌مارک صرفاً در سطح گروه `category_id` و برای دسته‌های دارای حداقل 3 پذیرنده عرضه می‌شود؛ داده یا هویت رقیب نمایش داده نمی‌شود.

## محدودیت‌های صادقانه

- بازه دیتاست از 2026-01-01 تا 2026-06-30 است؛ بنابراین تحلیل معتبر نوروز یا تاریخچه سالانه جلالی ارائه نمی‌شود.
- کوپایلوت فارسی پاسخ‌های قطعی و الگو-محور بر اساس تجمیع‌های محلی می‌دهد؛ اتصال زنده به LLM یا MCP ندارد.
- ستون دستگاه یا کانال پرداخت در دیتاست وجود ندارد، پس تحلیل mobile/desktop پرداخت ساخته نمی‌شود.
- فیلتر تاریخ، KPI فروش و روندهای روزانه/ماهانه را از تجمیع روزانه بازحساب می‌کند. تجمیع‌های مشتری، benchmark، کدهای خطا و ساعت/روز هفته در نسخه فعلی کل بازه دیتاست هستند و هنگام فیلترشدن با پیام محدودیت مشخص می‌شوند.

## سناریوی دمو

1. در نمای پیشخوان، پذیرنده را انتخاب و KPIها و پنل «روش محاسبه» را نمایش دهید.
2. تحلیل زمانی را باز کنید و پنجره اوج فروش، روند روزانه و توزیع ساعت/روز هفته را نشان دهید.
3. بخش مشتریان را باز کنید؛ نرخ خرید مجدد، RFM و مخاطبان در معرض ریزش را توضیح دهید.
4. در مقایسه صنفی، صدک و اختلاف با میانگین را نشان دهید و به پیام حریم خصوصی اشاره کنید.
5. سلامت درگاه را با قیف session/attempt، کد خطا و PSP مرور کنید.
6. در دستیار هوشمند یکی از پرسش‌ها را انتخاب کنید تا پاسخ، شواهد و اقدام پیشنهادی نمایش داده شود.
7. مرورگر را به عرض 390px تغییر دهید و ناوبری پایین و نمودارهای موبایل را نمایش دهید.
